\subsection{Run Manifest Template}
\label{sec:manifest_template}

Each experiment cell is defined by a YAML manifest entry containing:

\begin{verbatim}
- repo: psf/requests
  domain: networking
  task_family: swe-bench
  dataset_name: SWE-bench/SWE-bench
  source_prefixes: [requests]
  n_issues: 10
  issue_set_id: issues_swebench_requests_v2_10
  instance_ids:
    - psf__requests-1142
    - psf__requests-1327
    - ...
  evaluation_track: strict_commit_fidelity
\end{verbatim}

For same-snapshot runs, a \texttt{snapshot\_commit} field pins the repository state:

\begin{verbatim}
  evaluation_track: same_snapshot_amortized
  snapshot_commit: 22623bd8c265b78b161542663ee980738441c307
\end{verbatim}

Suite-level defaults include \texttt{manager\_max\_turns: 4}, \texttt{rag\_max\_turns: 4}, \texttt{repeats: 3}, and \texttt{seed: 17}.

\subsection{Deterministic Scoring Formula Details}
\label{sec:scoring_details}

The five scoring components from Equation~\ref{eq:deterministic_score} are computed as follows:

\begin{itemize}[leftmargin=1.5em]
  \item $S_{\text{sem}}(f)$: the maximum cosine similarity between the issue query embedding and any seed node belonging to file $f$.
  \item $S_{\text{graph}}(f)$: $\min(1, \log_2(1 + p) / \log_2(1 + P_{\max}))$ where $p$ is the number of unique graph paths reaching $f$ and $P_{\max}$ is the maximum across all candidate files. Edge-type diversity provides a secondary boost.
  \item $S_{\text{conf}}(f)$: the mean confidence weight along paths to $f$, with edge weights: high $= 1.0$, medium $= 0.6$, low $= 0.2$.
  \item $S_{\text{hint}}(f)$: token-level Jaccard overlap between the lowercased issue text and the file/module name.
  \item $S_{\text{pen}}(f)$: penalty applied when the file is reachable only through low-confidence paths or is a known ``hub'' node (high in-degree relative to the graph).
\end{itemize}

Default coefficients: $w_{\text{sem}} = 0.35$, $w_{\text{graph}} = 0.30$, $w_{\text{conf}} = 0.20$, $w_{\text{hint}} = 0.10$, $w_{\text{pen}} = 0.05$.

\subsection{Planned Ablations}
\label{sec:planned_ablations}

The following ablation experiments are planned to isolate component contributions:

\begin{enumerate}[leftmargin=1.5em]
  \item \textbf{Resolver confidence}: exclude low-confidence call edges during graph construction and measure the impact on retrieval quality.
  \item \textbf{Scoring component isolation}:
  \begin{itemize}[leftmargin=1.5em]
    \item Semantic only ($w_{\text{graph}} = w_{\text{conf}} = w_{\text{hint}} = w_{\text{pen}} = 0$).
    \item Graph only ($w_{\text{sem}} = w_{\text{hint}} = 0$).
    \item No confidence term ($w_{\text{conf}} = 0$).
    \item No penalty term ($w_{\text{pen}} = 0$).
  \end{itemize}
  \item \textbf{Agent budget sweep}: vary \texttt{max\_turns} from 2 to 8 for LLM-guided methods and measure quality--cost tradeoff.
  \item \textbf{Seed count}: vary $K_{\text{seed}}$ from 4 to 16 for the deterministic retriever.
  \item \textbf{Expansion depth}: vary BFS depth $D$ from 1 to 3.
\end{enumerate}

\subsection{Implementation Notes}
\label{sec:implementation_notes}

\paragraph{Dependencies.}
Key Python packages: \texttt{tree-sitter} ($\geq$0.24.0), \texttt{tree-sitter-python} ($\geq$0.23.0), \texttt{networkx} ($\geq$3.0), \texttt{faiss-cpu} ($\geq$1.7.4), \texttt{google-genai} ($\geq$1.0.0), \texttt{datasets} ($\geq$2.14.0).

\paragraph{Execution.}
Experiments are run via \texttt{run\_suite.py} with YAML configuration files. Single-repo experiments can also be run via \texttt{run\_experiment.py} with CLI arguments. Results are written to timestamped directories under \texttt{results/runs/} and aggregated repeat sets under \texttt{results/repeat\_sets/}.

\paragraph{Frozen artifacts.}
Report-ready numbers are generated by \texttt{research\_report/generate\_artifacts.py}, which reads raw results and produces a frozen bundle containing \texttt{manifest.json}, \texttt{summary\_bundle.json}, and LaTeX table exports.

\subsection{Attribution and Provenance}
\label{sec:attribution}

The graph construction pipeline in this project adapts resolver decomposition patterns from the open-source \texttt{code-graph-rag} project \citep{codegraphrag}. The adaptation is scoped to Python-first evaluation needs and does not import upstream product orchestration layers (Memgraph, MCP server, editing orchestration).
